PostgreSQL MVCC的介绍

PostgreSQL中的多版本实现是通过把原数据留在数据文件中，新插入一条数据来实现多版本的功能的。所以每张表上都有4个系统字段“xmin”、“xmax”、“cmin”、“cmax”。当两个事务同事访问记录时，通过参考xmin和xmax的标记判断记录的版本，根据版本号于自己当前的事务标识进行比较，确定自己的数据权限。当删除数据时，记录并没有从数据块中被删除，空间也没有立即释放。

PostgreSQL通过运行Vacuum进程（默认打开）来回收之前的存储空间，当一个表的更新量达到一定值时，AutoVacuum自动回收空间。

出于效率考量，当一个事务执行失败，在数据文件中该事务产生的数据并不会在事务回滚时被清理掉。PostgreSQL通过记录事务的状态来实现标记数据是有效还是无效，数据行上记录了xmin和xmax，只需要了解xmin和xmax对应的事务是成功提交还是回滚了，就可以知道这些数据行是否有效。PostgreSQL把实物状态记录在Commit Log中，简称CLOG，CLOG在数据目录的pg_clog子目录下。事务的状态有以下4种：

  • TRANSITION_STATUS_IN_PROGRESS=0x00：表示事务正在进行中
  • TRANSITION_STATUS_COMMITTED=0x01：表示事务成功提交
  • TRANSITION_STATUS_ABORTED=0x02：表示事务回滚
  • TRANSITION_STATUS_SUB_COMMITTED=0x03：表示子事务已提交

事务ID，缩写为xid，是一个32bit的数字，有以下3个特殊的事务ID是给系统内部使用的，代表特殊含义

  • InvalidTransactionId=0：表示无效事务ID
  • BootstrapTransitionId=1：表示系统表初始化时的事务ID
  • FrozenTransactionId=2：表示冻结的事务ID

所以数据库系统第一个正常的事务ID是从3开始，然后连续递增，达到最大值后，再从3开始。当再从3开始后，当数据库的年龄要超过2^31时，就把旧的事务换成FrozenTransactionId，当正常事务ID和冻结事务ID作比较时，会认为正常事务ID比冻结事务ID更新。

PostgreSQL MVCC的具体实现

实现所需的字段

在PostgreSQL种，每一样数据每一行数据（称为一个 Tuple，元组）的头部都包含几个关键的隐藏系统字段，分别是：

  • xmin：创建该版本的事务 ID。当插入（INSERT）或更新（UPDATE 会产生新版本）时设置。
  • xmax：删除/更新该版本的事务 ID。如果该版本当前未被删除，则为 0。删除（DELETE）或更新（UPDATE 旧版本）时设置。
  • ctid：当前版本的物理位置（块号+偏移量）。如果该版本被更新，这个字段会指向新版本的物理位置，形成一条版本链。
  • cid：事务内命令序号，用于区分同一事务内先后执行的命令。

DML操作具体如何触发版本变化：

  • INSERT（插入）：直接插入新行，设置 xmin = 当前事务 ID，xmax = 0。
  • DELETE（删除）：不物理删除行，只将待删除行的 xmax 设置为当前事务 ID，将其标记为“已删除”。
  • UPDATE（更新）：这是最关键的。UPDATE 逻辑上等价于 DELETE + INSERT。
    1. 旧行：将旧行的 xmax 设置为当前事务 ID（标记为已删除），并且将它的 ctid 指向新行的位置。
    2. 新行：插入一个全新的行，设置 xmin = 当前事务 ID，xmax = 0，ctid 指向自己。

如何判断某个版本是否可见

PostgreSQL不会去锁住正在被修改的行，每个查询在执行开始时，都会获取一个当前数据库状态的“快照”（Snapshot）。快照的核心内容是：当前这一刻，所有正在运行（未提交）的事务 ID 列表（xip），以及最小活跃事务 ID（xmin）和最大活跃事务 ID（xmax）。

  1. 检查xmin:
  • 如果xmin的状态是TRANSITION_STATUS_ABORTED，那么该条不可见
  • 如果xmin的状态是TRANSITION_STATUS_COMMITTED且不再当前活跃事务列表（xip）种，进入下一步检查（说明该行已提交）。
  • 如果xmin的状态是TRANSITION_STATUS_IN_PROGRESS或是自己的事务，需要配合cid做进一步判断。
  1. 检查xmax：
  • 如果xmax=0,可见
  • 如果xmax状态是TRANSITION_STATUS_IN_PROGRESS或TRANSITION_STATUS_ABORTED，可见
  • 如果xmax的状态是TRANSITION_STATUS_COMMITTED且在当前活跃事务列表之外，不可见

PostgreSQL MVCC的优劣

MySQL数据库的InnoDB的数据并不记录在原先的数据块中，而是被记录在回滚段中，如果要读取旧版本的数据，需要根据回滚段的数据重构旧版本数据。

PostgreSQL的多版本机制，在事务提交前只需要访问原先的数据，使得PostgreSQL实现了赌不阻塞写，写不阻塞读的极致并发能力，提交后，系统更新元祖的存储标识，直到Vacuum进程收回为止。其优点有：

  • 事务回滚可以立即完成，无论事务进行了多少操作。
  • 数据可以进行很多更新，不必像MySQL那样需要经常保证回滚段不会被用完。

劣势在于：

  • 旧版本数据需要清理。
  • 旧版本数据UI导致查询更慢一些，因为旧版本的数据存储于数据文件中，查询时需要扫描更多的数据块。
