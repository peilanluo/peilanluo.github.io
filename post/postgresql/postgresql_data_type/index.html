sql语句的分类

  • DQL：数据查询语句，基本上就是SELECT命令
  • DML：Data Manipulation Language的简称，即数据操纵语言，包括INSERT、UPDATE、DELETE三种。
  • DDL：Data Definition Language的缩写，数据定义语言，主要用于创建、删除，以及修改表、索引等数据库对象语言

数据类型

PostgreSQL支持的数据类型与其他数据库对比见下表：

分类名称 说明 与其他数据库对比
布尔类型 支持 与MySQL的BOOLEAN相同
数值类型 2字节smallint、4字节int、8字节bigint，十进制精确类型numeric，浮点类型有real和double precision。还有8字节货币（money）类型 无MySQL的unsigned整数类型，业务1字节长的tinyint和3字节长的midiumint
字符类型 有varchar(n)、char(n)、text三种类型 PostgreSQL中的varchar(n)最大可以存储到1GB，MySQL最大只能是64KB。PostgreSQL中的text类型相当于MySQL中的LONGTEXT。
二进制数据 只有byte 对应MySQL的BLOB和LONGBLOB类型
位串类型 位串就是一串1和0的字符串，有bit(n)、bit varying(n)两种 其他无此类型
日期和时间类型 有date、time、timestamp，time和timestamp又分是否包括时区的两种类型 PostgreSQL可以精确到秒一下，MySQL最多只能到秒。
枚举类型 等于某些编程语言中的enum类型 PostgreSQL使用枚举类型前需要先使用CREATE TYPE创建这个类型。
几何类型 包括了点（point）、支线（line）、线段（lseg）、路径（path）、多边形（polygon）、圆灯类型（cycle） 其他无此类型
网络地址类型 有cidr、inet、macaddr三种类型 其他无此类型
数组类型 可以存储一个数组 其他无此类型
复合类型 可以把已有的简单类型组合成用户定义的类型，就像C语言中的结构体一样 对应其他数据库自定义类型
xml类型 可以存储XML数据 其他无此类型
json类型 可以存储json类型数据 其他无此类型
range类型 范围类型，可以存储范围数据 其他无此类型
对象标识符 PostgreSQL内部标识对象的类型，如oid类型、regproc类型、regclass类型等 其他无此类型
伪类型 伪类型不能作为字段的数据类型，但是可以用于声明一个函数的参数或结果类型。有any、anyarray、anyelement、cstring、internal、language_handler、record、trigger、void、opaque 其他无此类型
其他类型 一些不好分类的类型都放这里，如UUID类型、pg_lsn类型 其他无此类型

以下是PostgreSQL一些特殊类型的详细解析。

JSON

JSON和JSONB类型都支持的操作符

  • -> int：取JSON数组的元素
  • -> text：通过key取JSON中的子对象
  • -» int：取JSON数组的元素，单返回结果是text类型
  • -» text：通过key取JSON中的子对象，但返回结果是text类型
  • #>text[]：通过指定路径取JSON中的对象，例如’{“a”:{“b”:{“c”:1}}}’::json#>’{a,b,c}’ 结果为1
  • #»text[]：通过指定路径取JSON中的对象，但返回结果是text类型

仅适用于JSONB的操作符

操作符 右操作数类型 描述 示例
= jsonb 两个JSON对象的内容是否相等 jsonb’[1,2]’ = jsonb’[1,2]’（t）jsonb’[2,1]’ = jsonb’[1,2]’（f）jsonb’{“a”:1, “b”:2}’ = jsonb’{“b”:2, “a”:1}’（t）
@> jsonb 左边的json对象是否包含右边的 json 对象 jsonb’{“a”:1, “b”:2}’ @> jsonb’{“b”:2}’（t）jsonb’[1,2]’ @> jsonb’[1]’（t）
<@ jsonb 左边的json对象是否包含于右边的json对象中 jsonb’[1]’ <@ jsonb’[1,2]'
操作符 右操作数类型 描述 示例
? text 指定的字符串是否存在于json对象中的 key 或字符串类型元素中。json 中的元素必须是字符串类型 jsonb’{“a”:1, “b”:2}’ ? ‘b’（t）jsonb’[“1”, “2”, “3”]’ ? ‘1’（t）jsonb’[1,2,3]’ ? ‘1’（f）
?| text[] 右值是一个数组，指定此数组中的任意一个元素是否存在于 json 对象的字符串类型的 key 或元素中。 jsonb’{“a”:1, “b”:2}’ ?| array[‘b’,‘c’]（t）jsonb’[“1”, “2”]’ ?| array[‘2’, ‘3’]（t）
?& text[] 右值是一个数组，指定此数组中的所有元素是否都存在于 json 对象中的 key 或者字符串类型元素中。 jsonb’{“a”:1, “b”:2, “c”: 3}’ ?& array[‘b’, ‘c’]（t）jsonb’[“1”, “2”, “3”]’ ?& array[‘2’, ‘3’]（t）

JSON类型的索引

无法在JSON类型的列上创建索引，但可以在JSON类型的列上建函数索引。JSONB类型的列上可以直接建索引，除了可以建BTree索引以外，还支持GIN索引。GIN索引可以高效的从JSONB内部的 key/value 对中搜索数据，一般情况下都会选择 GIN索引。

创建 GIN索引的语法如下：

1
2
3
4
5

# 使用默认的操作符创建
CREATE INDEX idx_name ON table_name USING gin (index_col);

# 使用jsonb_path_ops操作符建 GIN 索引：
CREATE INDEX idx_name ON table_name USING gin (index_col jsonb_path_ops);

默认方式（jsonb_ops）和 jsonb_path_ops的 GIN 索引区别在于，jsonb_ops的GIN索引中JSONB数据中的每个key和value都是作为一个单独的索引项，而jsonb_path_ops则只为每个value创建一个索引项。例如：有一个JSON数据“{“foo”: {“bar”: “baz”}}”，对于jsonb_path_ops来说，是吧“foo”“bar”“baz”组合成一个Hash值作为索引项，而jsonb_ops则会分别为“foo““bar”“baz”创建三个索引项。因为少了很多索引项，所以通常jsonb_path_ops的索引要比jsonb_ops的小很多，性能相应也会有提升。

jsonb_ops和jsonb_path_ops的对比：

  • jsonb_ops支持所有操作符
  • jsonb_path_ops仅支持@>、@?、@@，不支持?、?&、?|

一些特殊操作符

  • @>：包含，例如ARRAY[1,2,3] @> ARRAY[1,2]，ARRAY[1,2,3] @> ARRAY[2,1]，ARRAY[1,2,3] @> ARRAY[[1,2],[2,3]]
  • <@：被包含于，例如ARRAY[1,2] <@ ARRAY[1,2,3]
  • &&：重叠，是否有共同元素，例如ARRAY[1,2,3] && ARRAY[3,4](true)
  • ||：连接操作符，例如ARRAY[1,2]||ARRAY[3,4](结果{1,2,3,4})，1||ARRAY[2,3]

数据库逻辑结构

在一个PostgreSQL数据库系统中，数据的组织结构可以分为以下三层

  • 数据库：一个PostgreSQL数据库服务下可以管理多个数据库，当应用连接到一个数据库时，一般只能访问这个数据库中的数据
  • 表、索引：在PostgreSQL中表的术语为Relation。
  • 数据行：在PostgreSQL中行的术语一般为Tuple。

模式

模式（schema）是数据库中的一个概念，可以将其理解为一个命名空间或目录。不同的模式下可以有相同名称的表、函数等对象且互相不冲突。

在PostgreSQL中，一个数据库包含一个或多个模式，模式中又包含了表、函数及操作符等数据库对象。在PostgreSQL中可以认为模式的概念与MySQL中Database的概念是等同的。

创建模式的语法如下：

1

CREATE SCHEMA schemaname;

模式中表的访问一般采用`schema_*name.table_*name`的模式，如果没有创建特定的模式，默认会存放在公共模式中，访问公共模式中的表不需要加schema前缀。

索引

PostgreSQL中支持一下几类索引：

  • BTree：最常用的索引，BTree索引适合处理等值查询和范围查询。
  • HASH：只能处理简单的等值查询。
  • GiST：不是单独一种索引类型，而是一种架构，可以在这种架构上实现很多不同的索引策略。
  • SP-GiST：SP-GiST是“Space-Partitioned GiST“的缩写，即空间分区GiST索引。主要是通过一些新的索引算法来提高GiST索引在某种情况下的性能。
  • GIN：反转索引，可以处理包含多个键的值，如数组等。比如@>、<@、=、&&都是PostgreSQL提供的GIN操作符。

一些创建索引的语句

# 按降序创建索引
CREATE INDEX idx_a ON table_name(a DESC);
# 如果字段a中有空值，则可以在创建索引时指定空值排在非空值前面
CREATE INDEX idx_a ON table_name(a DESC NULLS FIRST);
# 空值排非空值后面
CREATE INDEX idx_a ON table_name(a DESC NULLS LAST);

事务相关

在PostgreSQL中，默认的隔离级别是读已提交。

两阶段提交

PostgreSQL支持两阶段提交，可以实现多台数据库之间的原子性，是实现分布式事务的关键。两阶段提交的步骤如下：

  1. 应用程序先调用各台数据库做一些操作，但不提交事务。然后应用程序调用事务协调器中的提交方法。
  2. 事务协调器将联络事务中涉及的每台数据库，并通知它们准备提交事务，这是第一阶段的开始。PostgreSQL中一般是调用PREPARE TRANSACTION命令。
  3. 各台数据库PREPARE TRANSACTION命令后，如果要返回成功，则数据库必须将自己置于以下状态：确保后续能在被要求提交事务的时候提交事务，或后续能在被要要求回滚事务的时候回滚事务。所以PostgreSQL会将已准备好提交的信息写入持久存储区内，如果数据库无法完成此事务，会直接返回失败给事务协调器。
  4. 事务协调器接收所有数据库的响应。
  5. 在第二阶段，如果任何一个数据库在第一阶段返回失败，则事务协调器将会发一个回滚命令“ROLLBACK PREPARED”给各台数据库。如果所有数据库的响应都是成功的，则向各台数据库发送COMMIT PREPARED命令，通知各台数据库事务成功。

使用两阶段提交首先需要设置参数，再重启数据库：

set max_prepared_transactions = 10;
